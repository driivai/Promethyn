## Clean categories — stated explicitly

- **Secrets & credentials (full history): NOTHING FOUND.** No cloud-LLM provider API keys (the `sk-…` / `sk-ant-…` families), no GitHub/PyPI/AWS tokens, JWTs, or private-key blocks in HEAD or any of the 262 commits. **The session's real Postgres password (`m1gr@te-…`) has zero hits anywhere** — it was never committed (tests and the demo read it from `PROM_CHOKEPOINT_PG_*`). No `.env`, `.pypirc`, `.netrc`, `id_rsa`, or `*.pem/*.key` was ever added on any ref. The only "password" literals are the ephemeral CI value (L3) and obvious test fixtures (`password="secret"`, `"rotatable-secret"`, `"new-secret"`) — no real DB credential, connection string, or internal hostname. The one private IP (`10.0.0.9`) is a fake wrong-target test fixture.
- **Injection / unsafe deserialization in the hot paths: NOTHING FOUND.** No `eval` / `exec` / `shell=True` / `os.system` / `pickle.loads` / `yaml.load` anywhere in `src/`. The chokepoint's PostgreSQL access is parameterized (`%s`) throughout, and the one dynamic identifier (the bound schema) goes through `set_config('search_path', pg_catalog.quote_ident(%s), true)` — injection-safe. The single f-string in SQL (`CREATE SCHEMA {_RECEIPT_SCHEMA}`) interpolates a **module constant**, not input. The migration artifact SQL executing as-is is the authorized action by design, not an injection.
- **Professional polish: NOTHING FOUND.** Zero `TODO`/`FIXME`/`HACK`/`XXX` anywhere in `src/`. No profanity, snark, or disparagement in code, docs, or the demo. No debug prints, `breakpoint()`, or commented-out code blocks in the chokepoint / gate / ledger.
- **Overclaim: NOTHING FOUND.** The README keeps the honest "IS NOT a finished product — alpha, one protected action today" line. "enterprise-grade" and "SOC 2 evidence exports" appear only in `docs/open-core-boundary.md`, explicitly framed as *potential commercial* scope, not present claims. No invented integrations.
- **Internal/confidential leakage: NOTHING FOUND** beyond L4's self-referential list. No customer names, financial data, or business-confidential detail; the codenames have zero real occurrences.
- **Vendor/AI artifacts in code on `main`: clean.** The 3 assistant-authored commits live only on the stale vendor-named branches (M3), never on `main`; the assistant tokens on `main` are confined to one commit body (M2). No such tokens in `src/`, the docs, or the demo (the hygiene guard enforces this on every build).

## Security posture (bank reviewer's skim)

Strong for an alpha: minimal supply chain (one runtime dependency, lazily imported), Apache-2.0, injection-safe DB access, a real enforcement boundary with a committed six-path isolation proof, and a tamper-evident hash-chained ledger. The CI is unusually honest — it sets `PROM_REQUIRE_PG=1` and `PROM_REQUIRE_SANDBOX=1` so the live-Postgres and isolation tests **must run, never skip**, and forces `fetch-depth: 0` so the Hearth-diff guards actually execute. The one dent is M1: that same live suite is not portable to every local Postgres/psycopg build.

## Honest-state summary (#6)

If a bank security team cloned this today, the first impression is **credible for an early-stage enforcement core**: a small, readable, Apache-2.0 codebase with one dependency, no secrets, no unsafe primitives, injection-safe database access, and a README that states its own limits instead of overselling. The **top three things that would give them pause** are: **(1)** a personal Gmail and an unfamiliar name ("Benji Franclin") on 100% of the git history (H1) — read as either a privacy slip or a provenance question; **(2)** AI-assistant fingerprints in the history and branch list — vendor-named branches, a vendor `noreply` co-author, and assistant session URLs in a commit body (M2/M3) — not disqualifying, but a bank will notice and may ask about AI-authorship and IP provenance; and **(3)** `pytest` is not green out-of-the-box on their own Postgres (M1), which undercuts "clone it and run it yourself" unless their stack matches CI. None are CRITICAL, and all are addressable before the conversation — the identity and branch cleanups are quick, and M1 is a contained type-normalization fix in a security-relevant path worth doing first.
